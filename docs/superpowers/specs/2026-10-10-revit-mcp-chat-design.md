# Revit MCP Chat — дизайн первого выпуска

Дата: 2026-10-10. Статус: документ утверждён пользователем; основа для плана реализации.

## Цель и границы

Создать отдельный открытый add-in для Autodesk Revit 2022–2024. Он показывает закрепляемую панель чата, через которую пользователь общается с ИИ и работает с текущей моделью через уже установленный [`rvt-mcp`](https://github.com/yakovman1/rvt-mcp). Первый выпуск включает историю чатов, настройки провайдеров и ключей, чтение модели, а при доступных изменяющих инструментах — подтверждаемое изменение модели. Пользователь должен видеть, к какой модели подключён чат и что делает агент.

Первый выпуск поддерживает OpenAI, Anthropic, Gemini, DeepSeek, Alice AI LLM через Yandex AI Studio, GigaChat и произвольный OpenAI-совместимый API. Архитектура адаптеров позволяет добавлять другие протоколы без изменения панели и механизма MCP. «Любой сервис» означает возможность добавить адаптер; неизвестные протоколы не будут автоматически работать без адаптера.

`rvt-mcp` остаётся отдельным продуктом и устанавливается отдельно. Чат не реализует Revit-команды и не обращается к внутреннему TCP-протоколу плагина напрямую. Поддержка Revit 2025+ и автономная установка `rvt-mcp` не входят в первый выпуск.

## Архитектура

1. **Revit add-in** под .NET Framework 4.8 регистрирует закрепляемую WPF-панель в Revit 2022, 2023 и 2024. Он получает идентичность активного документа через Revit API, отображает чат и передаёт пользовательские действия локальному агенту. Долгие сетевые запросы не выполняются на UI-потоке Revit.
2. **Локальный агент** — отдельный процесс .NET 8 под учётной записью пользователя. Панель обменивается с ним сообщениями через локальный канал с ограничением доступа для текущего пользователя. Агент ведёт цикл диалога, хранит историю и ключи, вызывает API ИИ и выступает MCP-клиентом.
3. Агент запускает отдельный процесс **`rvt-mcp` MCP-сервера** и общается с ним через stdio по MCP. Существующий `rvt-mcp` add-in принимает команды от своего сервера и выполняет их в Revit. Агент явно привязывает сервер к PID того процесса Revit, в котором открыта панель; при потере цели не перепривязывается к другому процессу без проверки.

У каждого процесса Revit своя сессия панели и агента. Если `rvt-mcp` не установлен, не запущен, недоступен или занят другим клиентом, панель показывает состояние и понятное действие для повторного подключения. Она не отбирает соединение у другого клиента.

Запуск агента, его остановка вместе с Revit, повторный запуск после сбоя и восстановление истории являются частью жизненного цикла add-in. Отсутствие интернет-соединения не мешает просматривать локальную историю.

## Провайдеры и модели

Адаптер провайдера преобразует общий формат сообщений и вызовов инструментов в конкретный API, включая потоковые ответы, ошибки и учётные данные. Выбранный провайдер и идентификатор модели задаются в настройках и сохраняются в записи чата. Для произвольного OpenAI-совместимого сервиса пользователь вводит адрес API и идентификатор модели. Предустановленные профили содержат адреса и требуемые дополнительные поля, но не пользовательские секреты.

Для Alice AI LLM используется API Yandex AI Studio и его требования к каталогу и авторизации. Для GigaChat агент обменивает ключ авторизации на краткоживущий токен и обновляет его; токен держится в памяти. У моделей и сервисов различается поддержка вызова инструментов. Если выбранная модель не поддерживает их, чат может отвечать текстом, но панель явно показывает, что работа с Revit через MCP для этой модели недоступна.

Агент получает реальный каталог инструментов через MCP `tools/list`. Чтобы не отправлять сотни схем в каждый запрос к модели, он выбирает релевантные инструменты из доступного каталога и расширяет выбор при необходимости. Он вызывает только инструмент, присутствующий в текущем каталоге, с параметрами, прошедшими проверку схемы.

## Ключи и настройки

Ключ пользователя хранится отдельно для каждого провайдера в профиле Windows с защитой DPAPI для текущей учётной записи. Настройки позволяют добавить, заменить, проверить и удалить его; значение не показывается после сохранения. Обычные настройки, такие как адрес API, модель и идентификатор каталога, сохраняются отдельно от секретов.

Администратор может передать ключи для выбранных провайдеров на этапе сборки установочного пакета. Реальные значения не попадают в открытый репозиторий, исходники по умолчанию, логи или конфигурационные файлы установки. В интерфейсе отображается только наличие подготовленного доступа, не сам ключ. Поскольку секрет поставляется внутри настольного приложения, пользователь с доступом к бинарным файлам или процессу потенциально способен его извлечь; это принятый компромисс, а не защита от извлечения.

Для активного провайдера приоритет таков: ключ пользователя → ключ, подготовленный администратором → сообщение о необходимости настроить доступ. Неверный пользовательский ключ вызывает явную ошибку и **не** приводит к автоматическому расходованию администраторского ключа. После удаления пользовательского ключа агент снова использует подготовленный ключ, если он есть. Секреты исключаются из истории, диагностики и текста ошибок.

## Панель и история

Панель содержит вкладки **Чат**, **История** и **Настройки**. Чат показывает текущую модель Revit, провайдера, ИИ-модель, состояние MCP, сообщения, вызовы инструментов и запросы подтверждения. Вкладка «История» по умолчанию показывает чаты текущей модели; переключатель «Все чаты» открывает общий список. Пользователь может создать, открыть, переименовать и удалить чат.

История хранится локально в профиле Windows и включает сообщения, время, провайдера и модель ИИ, вызовы MCP, решения пользователя и результаты. Ключи и полные тела произвольного C# кода в историю не записываются; для `send_code` сохраняется только краткая запись о факте вызова и его исходе. Чат другой модели доступен для чтения, но вызовы MCP в нём блокируются до открытия соответствующей модели. Для сохранённых файлов идентичность модели строится из её расположения (с учётом центральной модели, если применимо); для несохранённого документа используется временная идентичность текущей сессии, которая закрепляется при первом сохранении. После Save As исходный чат остаётся связанным с исходной моделью; новая копия получает собственную историю.

Хранилище истории — локальная база SQLite с версией схемы и миграциями. Она принадлежит текущему пользователю Windows. Экспорт и синхронизация истории между машинами не входят в первый выпуск.

## Режимы MCP и подтверждение изменений

Режимы доступа задаются в самом `rvt-mcp` его существующей конфигурацией и параметрами запуска. **В панели чата нет переключателя «Разрешить изменения»**. Агент использует фактически доступный каталог инструментов: при `read-only` доступны только разрешённые им инструменты; при более широком наборе изменяющие команды могут вызываться после подтверждения.

Автоматически выполняется только инструмент, который положительно определён как не изменяющий модель. Неизвестный или изменяющий инструмент требует подтверждения. Перед вызовом панель показывает имя, назначение и фактические параметры. Пользователь может выполнить или отклонить вызов; отклонение возвращается в диалог как отказ, без обращения к Revit. `revit_send_code_to_revit`, если предоставлен сервером, всегда требует отдельного подтверждения с полным видимым C# кодом. Пакетный вызов показывает все входящие команды перед общим подтверждением.

После подтверждения панель показывает выполнение и результат. При тайм-ауте или потере ответа на изменяющую команду агент считает исход неизвестным и не повторяет её автоматически; сначала требуется проверить модель. Отмена диалога останавливает ещё не отправленные действия и генерацию, но не обещает откат уже выполняемой транзакции Revit.

## Установка и обновление

Установочный пакет размещает add-in и манифесты для обнаруженных Revit 2022–2024, а также локальный агент .NET 8. Он проверяет наличие совместимой установки `rvt-mcp`; при отсутствии показывает ссылку и инструкцию, не устанавливая его автоматически. Обновления чата и `rvt-mcp` независимы. Пакет без администраторских ключей полностью работоспособен при вводе пользовательского ключа. Публичная сборка не содержит реальных ключей.

Версия и расположение `rvt-mcp` проверяются до запуска MCP-сессии. Несовместимость отображается в панели как диагностика с инструкцией по обновлению. Удаление чата не удаляет `rvt-mcp` и не стирает пользовательскую историю без явного выбора пользователя.

## Проверка и критерии готовности

- Автоматические проверки покрывают нормализацию вызовов всех заявленных провайдеров, выбор ключа и ошибки авторизации, локальную историю и привязку к модели, классификацию инструментов, подтверждение и отказ, потерю ответа на запись, переподключение MCP и обработку ошибок.
- Контрактные проверки работают с имитацией MCP-сервера и его каталогом инструментов; они не должны требовать запущенного Revit.
- Ручная проверка в Revit 2022, 2023 и 2024 подтверждает загрузку add-in, закрепление панели, определение активной модели, чтение через `rvt-mcp`, отклонение изменяющего вызова до исполнения, подтверждённое изменение и корректное поведение в `read-only`.
- Выпуск готов, когда пользователь может установить отдельный add-in рядом с `rvt-mcp`, выбрать поддерживаемого провайдера, начать и восстановить чат для модели, выполнить чтение и безопасно подтвердить доступное изменение без раскрытия ключа в UI или конфигурации.
